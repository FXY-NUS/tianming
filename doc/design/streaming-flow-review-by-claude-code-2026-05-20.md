## 1. 整体诊断

视觉语言到位 · North Star 命中度高 · 但 3 条**硬约束**被破必须改 · 关键的多简历 / 推荐简历层完全缺失（Phase 4.6 brief 对应内容没融入）。

**做对的**（v2 保住别动）：

- ✅ 卦象徽章 + 卦曰一句话解读（"建议投但合同读三遍"完美命中犹豫型用户的"我需要一句外部锚"诉求）

- ✅ 暗色背景 + 古典中文宋体 + 英文 italic 混排（沿用 §10.3 提到的"天命导航仪 Design System"基线）

## 2. P0 · North Star 硬约束（必改）

### 2.1 缺"next →"次要按钮
- **出处**：HANDOFF §5 Phase 7 §537 明确：「屏中央 1 张大卡片...一个大『📋 帮我投这个』按钮 **+ 一个低权重『next →』按钮**」
- **现状**：5 张 mock 底部只有一个金边线框的"帮我投这个"
- **风险**：用户跳过当前 JD 的路径没有 → 强行二选一会让犹豫型用户更卡
- **改法**：主按钮右侧加一个权重明显更低（线框透明 / 灰色文字）的"先放一放 →"或"看下一张 →"按钮；视觉权重对比建议 4:1

### 2.2 缺屏底 4 张半透明预览小卡
- **出处**：HANDOFF §5 Phase 7 §537 明确：「**屏底 4 张半透明小卡片预览下一批**」+ "设计参考 Spotify Discover Weekly"
- **现状**：5 张 mock 都是单卡满屏，屏底空白
- **风险**：用户不知道"后面还有"→ 当前张稍微不喜欢就会担心"是不是就这一张" → freeze
- **改法**：主卡下方约 20% 屏高加 4 张极简预览小卡（只显示职位标题 + 公司 + 卦象 + 分数色块）；透明度 30-40%；轻轻虚化背景；视觉重心仍在主卡

### 2.3 第 5 屏底部「系统已为你过滤 87 个不合适的」暴露具体数字
- **出处**：HANDOFF §1.5 §96 是**硬约束**：「主页暴露任何"过滤数字 / 桶 / 漏斗 / 固定 picks 数量"——理由：更多选项 ≠ 更多信任，犹豫型用户看到『我们扔了 83 个』会去点 Skip 桶自我撤销过滤」
- **现状**："87 个" 是具体数字
- **注意**：HANDOFF §537 描述里写「『系统已为你过滤 N 个不合适的 · 看完整列表』作 escape hatch」——这里的 N 是 **placeholder**，**不是要真显示数字**。Mock 把 placeholder 当真值导出了
- **改法**：直接删 "87 个"，改成"看完整列表"或"还有更多"；不要任何数字

## 3. P1 · 强烈建议

### 3.1 缺 Phase 4.6 推荐简历 banner / 多简历切换入口
- **背景**：用户有多份简历时，Pro 深审会输出 `recommended_resume = { resumeId, label, reasoning, edits_suggestion }`（详见 `doc/briefs/claude-design-phase-4-6-recommended-resume.md`）
- **现状**：当前 mock 完全没体现这层
- **改法**：在卦曰横条下方、技能/文化/成长徽章上方，加一个非阻塞 banner：
  - 标题："建议用『技术岗版』投这个职位"
  - 一句话 reasoning
  - [切换] [看建议] 两个轻量按钮
  - 折叠后展示 `edits_suggestion` 列表
- **状态**：仅在 `recommended_resume.resumeId !== activeResumeId` 时显示；相等时隐藏

### 3.2 截止日期视觉太轻
- **现状**：右上角"6月15日截止 / 7月1日截止"用了跟"via LinkedIn"同等级的灰色小字
- **风险**：对犹豫型用户，截止日期是**重要的 urgency 推动力**，淡化是反 North Star 的
- **改法**：≤ 7 天截止的加一个 amber/rose 色 badge "⏳ 6 天后截止"；≤ 3 天加更强烈视觉（图标 + 文字加粗）；长期有效保持现状

### 3.3 缺"先放一放，再考虑"轻量动作
- **现状**：只有"投" / "下一张"（如果 P0 §2.1 补了）
- **缺**：犹豫型用户经常的需求"我喜欢这个，但今天不投，过两天再决定"
- **改法**：卡片右上角小图标"🔖 收藏"或"⏰ 提醒我"——不进决策流，单纯标记到"我的收藏夹"

## 4. P2 / P3 · 视觉细节 + 补 mock

### 4.1 视觉细节
- **金色冲突**：卦曰横条边框金 + "帮我投这个"主按钮金 → 视觉权重没分级。建议主按钮加 glow/emboss，卦曰边框降为半透明描边
- **第 2-5 屏顶部 logo / "STREAMING FLOW · 岗位推荐" header 缺失**：第 1 屏有，后 4 屏无 → 确认是 fade 设计还是 PDF 导出 bug
- **PROS / CONS 排版**：英文小写 italic 跟中文宋体 baseline 不齐，间距可精细
- **三个分数 92/89/78 精确数字**：是代码算出的 overall，不违反"过滤数字"硬约束，可保留；但**建议考虑**用色块 / A/B/C 等级替代精确数字——犹豫型用户看到"81 而不是 82"可能陷入纠结。这是设计 tradeoff 值得讨论

### 4.2 缺三屏 mock（让 v2 一起补）
- **(a) 屏底预览卡片态**：滚动 / 切换时预览卡如何切入主位
- **(b) Phase 4.6 推荐简历 banner 嵌入态**：banner 出现 / 折叠 / 切换简历的不同状态
- **(c) Apply Assistant L2 modal**：点了"帮我投这个"后弹出的结构化字段一键复制弹窗（HANDOFF §5 Phase 5.5）
